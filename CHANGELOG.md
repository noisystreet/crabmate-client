# Changelog

User- and maintainer-facing changes for **crabmate-client** (official Client shells + business UI).

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning is intended to follow [Semantic Versioning](https://semver.org/).  
Server-side changes (contracts / SSE / CORS, etc.) live in [CrabMate](https://github.com/noisystreet/CrabMate) and are not duplicated here.

On release: move `[Unreleased]` entries into a new version section and tag (e.g. `v0.1.1`). Write maintainer-readable summaries; do not list every internal commit.

## [Unreleased]

### Added

- **Design system: component-look tokens, so the `shadcn` presets now look like shadcn/ui and not only use its palette.** Five tokens move what used to be hard-coded in `frontend/styles` behind a per-theme switch: `--focus-ring-color` (default `var(--accent)`) — the shadcn presets point it at their neutral zinc foreground, since shadcn reserves the accent for interactive state and the focus ring should not also be the brand color; `--label-transform` + `--label-tracking-scale` (default `uppercase` + `1`) — shadcn sets `none` + `0`, which turns the twelve all-caps / letter-spaced section titles, table headers and group labels into regular case with no tracking, each site keeping its own ratio as `calc(<ratio> * var(--label-tracking-scale))` so one coefficient scales them all; and `--btn-primary-shadow-hover` / `--btn-primary-shadow-active` (default: the inset top-light plus the accent halo) — shadcn sets both to `none`. They are defined in `tokens.css` and explicitly in all five theme files (the theme-coverage union rule makes that mandatory; the four non-shadcn presets restate the current values, so their rendering is unchanged), and consumed by `components.css`, whose focus rule now reads `--focus-ring-color` and whose primary-button `:hover` / `:active` read the two shadow tokens. The six focus-ring sites across the stylesheets (`approval.css` / `components.css` / `modal.css` / `layout-chat.css` / `status.css` / `shell-ds.css`) switch from `var(--accent)` to `var(--focus-ring-color)`. The shadcn primary button also drops its gradient and inner glow: `--btn-primary-bg` becomes a flat fill (the top stop of the old gradient — ≈5.5:1 on the dark preset and ≈5.8:1 on the light one, still AA for the white label), `--btn-primary-border` and `--inset-highlight` become `transparent` (the latter neutralising the resting inset hairline without a separate token) and both shadow tokens are `none`.
- **Maintainer tooling: the CSS literal budget gate also counts `border-radius` literals.** The third dimension joins `font-size` and color in `scripts/check-css-literals.sh` / `scripts/css_literals_check.py`: every `border-radius` carrying a unit (`px` / `rem` / `em` / `%` — a bare `0` is not counted, corner variants are covered) is counted per file, and `var(--radius-x, 5px)` fallbacks count too, because a fallback only applies when the token is missing and is exactly where a second source gets written in. The budget format grows to `<path>  font-size=<n>  color=<n>  border-radius=<n>`, the stale-entry rule now fires when all three counts are 0, and `scripts/css_literals_budget.txt` registers the 15 survivors (six sizes outside the `--radius-*` ladder — hairlines, `50%`, the chat bubble, the em-based toggle — plus nine `var()` fallbacks). Adding the dimension came with an eight-literal pass onto the ladder: `999px` → `--radius-pill` (the workspace clone bar and its fill, the composer's capsule chip), `4px` → `--radius-xs` (the IDE menu trigger) and `6px` → `--radius-sm` (both shell-topbar menus, the composer slash menu and its banner). The `6px → var(--radius-sm)` swap is the one visible change: `material-dark` sets `--radius-sm` to `8px`, so its four menu / capsule corners move 6px → 8px (every other preset already had `--radius-sm: 6px`).
- **Design system: the `shadcn-dark` / `shadcn-light` presets get a flat primary button and neutral focus ring** (see the component-look tokens above). Beyond the token definitions, the two preset files stop using the family's gradient-and-halo primary treatment: a single flat fill, a transparent border, and `box-shadow: none` on hover and active — the shadcn button is a flat rectangle whose feedback is the fill change, not a bevel.

## [0.5.2] - 2026-09-25

### Added

- **Android: the notification channel names and descriptions now follow the app's in-app language.** `StreamKeepAliveService.ensureChannels()` used to read the Chinese strings unconditionally, so an English user saw a Chinese channel name in the system notification settings. It now picks between the Chinese resource and a new `<name>_en` sibling through the same `StreamKeepAliveText.isEnglish(localeSlug)` helper the notification body already used — the repo's convention is `_en`-suffixed resources driven by the app language, not a `values-en/` folder, because the two can differ. `createNotificationChannel` is safe to re-call (only behavioral fields like importance are frozen at first creation), so a language switch is picked up on the next `onStartCommand`.
- **Maintainer tooling: design-token mirror gate**. New `scripts/check-token-mirrors.sh` (pre-commit hook + part of `check.sh`) keeps every non-CSS surface that can only restate a token honest against the single source, `:root` in `frontend/styles/tokens.css`: (1) `res/values/colors.xml` must define exactly the `cm_<token>` mirrors of the consumed tokens (`bg` / `surface` / `text` / `muted` / `accent` / `error`) with matching values and no extra literal colors; (2) `res/values*/themes.xml` must contain no color literal, and `Theme.crabmate_mobile` must reference `@color/cm_bg` for its four background slots and declare both system-bar light-icon flags `false`; (3) the boot backgrounds of `frontend/index.html`, `desktop-tauri/splash.html` and `crates/crabmate-connect/assets/connect.html` must equal `--bg`; (4) every `@color/<name>` referenced from `res/values*/themes.xml` must actually be declared in `res/values*/colors.xml` (a typo like `cm_textt` would otherwise only surface as an AAPT build failure); (5) hand-written Kotlin under `.../java/edu/crabmate` (the same scope `scripts/ktlint-android.sh` uses, i.e. excluding Tauri's generated sources) may only consume the `cm_*` mirrors — a direct `R.color.<other>` would bypass the whole chain, since any value can be written there. All five rules are exact-equality with no allowlist, and each boot-background declaration must match exactly once, so a renamed or relocated declaration fails instead of silently disabling the check.
- **Icons: one shared inline-SVG template, size tokens, and theme-following glyphs promoted to real icons** (design and open follow-ups: `docs/design/icon_unification.md`). Icon sizes move to three tokens in `tokens.css` (`--icon-sm` 8.75px / `--icon-md` 12.25px / `--icon-lg` 15.75px, the same 14px root anchor as `--text-*`) instead of per-declaration literals, each tier keyed to the rendered size of the glyph it replaced; the last three size literals (in `modal.css`) moved onto `--icon-md` / `--icon-lg`, so `frontend/styles` is now free of icon-size literals. Text glyphs that can live in the DOM and must follow the theme are now SVG (`×` `‹` `›` `▾` `▸` `✓` `−` `↑` `↓` `⌕` `□` `+`); the ones that are typographic symbols, CSS `content`, or have no DOM replacement point stay text (the `…` loading status, which is also a `role="status"` accessible name — an icon would leave it with none; the lightbox `×` and the tool-card expander `▸` built as HTML strings outside the Leptos view tree; the tool-card emoji set; the `●` dirty dot, the `—` empty-value placeholder, and `◈` / `▾` in `content`). The data-URI chevron keeps its per-theme copies: the planned `mask-image` step was withdrawn under its own precondition (WebKitGTK + Android WebView mask support must be verified on device, which this repo cannot do). That precondition was then cross-checked as far as versions allow: **WebKitGTK 2.52.6** (local, Debian 13 trixie) is well past the Safari 15.4 / WebKitGTK 2.36 threshold for **unprefixed** `mask-image` (`-webkit-mask-image` goes back much further), so the desktop Linux shell is clear, while **Android WebView** tracks Chromium and needs **120+** for the unprefixed form (`minSdk 24` and Play-Store self-updates make that impossible to assert at build time); on-device rendering confirmation stays a manual step, and an attempt to automate it (sampling pixels from a `WebKit2.WebView` snapshot) was dropped for the missing `python3-gi-cairo`.
- **Maintainer tooling: icon gate**. New `scripts/check-icons.sh` (pre-commit hook + part of `check.sh`) keeps icons at one template source and one size source: no literal `<svg` in `frontend/src/**/*.rs` outside `frontend/src/icon.rs` (every inline SVG must go through the `Icon` component or an `icon_*` helper — which also closes the "inline a `<svg>` inside an HTML string / `set_inner_html`" shortcut), and in `frontend/styles/*.css` any `svg` type-selector rule's `width` / `height` (including `min-` / `max-`) must be `var(--icon-*)`. `svg` is matched as a type selector only, so `.btn-send-icon-svg`, `data:image/svg+xml` and `url(…svg)` are not false positives, and `@media`-nested rules are checked too. Intentional exceptions opt out in place with `icon-gate: allow <reason>` (on the Rust line, or in the CSS rule's leading comment) — verified not to leak to the next rule. **Known blind spot**, documented in the script and in `AGENTS.md`: it does not verify that a class name and the `<svg>` element are the *same* element, so a never-matching descendant selector like `.container svg` still counts as evidence for `.container`; that regression class (the 2026-09-25 `workspace-tree-chevron` one, where the wrapper `<span>` was dropped and the container box size landed on the `<svg>`) still needs code review.
- **Maintainer tooling: modal shell gate**. New `scripts/check-modal-shell.sh` (pre-commit hook + part of `check.sh`) keeps `role="dialog"` / `role="alertdialog"` and `aria-modal` owned by the shared shell: none of them may appear in `frontend/src/**/*.rs` outside `frontend/src/app/focusable_menu.rs`, which is where `FocusableModalPanel` emits them. The imperative equivalent is caught too (`set_attribute("role", "dialog")`), while passing `dialog_role="dialog"` **to** the shell is not (the match requires a non-identifier character before `role`, so `dialog_role` never trips it). Intentional exceptions opt out in place with `modal-gate: allow <reason>` on the offending line; the one current exemption is the chat image lightbox, which builds its overlay through `create_element` / `set_attribute` outside the Leptos view tree and therefore cannot use a component.

- **Maintainer tooling: package-list single source + mechanical boundary guards** (see `docs/adr/0004-multi-client-repo-maintenance.md`). New `scripts/rust-pkg-dirs.txt` is the only place listing the nine Rust packages; the `Makefile` `fmt` / `clippy` / `clean` targets and `scripts/check.sh` now loop over it. New `scripts/check-boundaries.sh` (pre-commit hook + part of `check.sh`) mechanically enforces `crabmate-client-api` dependency purity (no reqwest / tokio / tauri / web-sys / wasm-bindgen), `crabmate-connect` default features staying Tauri-free, the exact crates.io `crabmate` contract-pin shape (`default-features = false, features = ["protocol"]`, no legacy `crabmate-sse-protocol`) across all manifests, and version consistency across all packages. New `scripts/set-version.sh <semver>` bumps all package versions and their `Cargo.lock`s in one step.

- **Maintainer tooling: responsive breakpoint single source**. New `scripts/check-css-breakpoints.sh` (pre-commit hook + part of `check.sh`) asserts every stylesheet `@media` agrees with `MOBILE_LAYOUT_BREAKPOINT_PX` in `frontend/src/app_prefs.rs`: the narrow query must be `max-width: N` and its complement `min-width: N + 1` (cross-written pairs are rejected — they overlap, or make `N` itself ambiguous), and any other breakpoint (the 900px settings-modal one) must be registered in the script with its purpose. It also fails when the Playwright mobile spec's viewport no longer falls on the narrow side. `@media` conditions cannot use `var()` and Trunk does not preprocess CSS, so the value stays repeated under this guard instead of being injected.
- **Maintainer tooling: class-name contract gate**. New `scripts/check-css-contract.sh` (pre-commit hook + part of `check.sh`) fails when a class name emitted by this repo's consumers has no rule in the same scope's CSS (P5 of the P0 class-contract audit). Scopes are isolated — `frontend` (stylesheets + `index.html` inline `<style>` vs. `src/**/*.rs` + `index.html`), and the self-contained `connect.html` / `splash.html` pages — and collection reuses the audit's evidence-backed heuristics (`class="…"`, `class=("…", …)`, `class:NAME=`, `fn *_class` bodies, co-occurrence with a known class, `is-*`), so i18n copy and test assertions are not mistaken for class names and tokens used only as `data-*` values are treated as noise. Third-party vendor runtime classes (`cm-*`) are deliberately out of contract. The 16 existing names that have no rule are all intentional semantic / layer hooks sharing an element with an existing base class (e.g. `approval-modal-backdrop` on `.modal-backdrop`, `tauri-win-ctrl-minimize` on `.tauri-win-ctrl`, `settings-mcp-tools-col-name` sized by its header grid); each is registered in `scripts/css_contract_allowlist.txt` with a per-entry reason, and a *stale* entry (rule since added, consumer removed, scope typo) fails as well so the allowlist cannot rot into a blanket exemption.
- **Maintainer tooling: design-token gate**. New `scripts/check-css-tokens.sh` (pre-commit hook + part of `check.sh`) scans `frontend/styles` + `frontend/themes` together and fails on (1) a `var(--x)` whose `--x` is never defined in that scope, and (2) a `var()` fallback containing a color literal (`#hex` / `rgb()` / `hsl()` / `white` / `black`) — a missing token then silently renders a fixed light color instead of following the theme. Attributes the stylesheets cannot define by construction are the intentionally runtime-injected ones (Rust `style.setProperty`, Leptos inline `style=…`, the Android IME inset), registered in `scripts/css_tokens_allowlist.txt` with a per-entry reason; a *stale* entry (now defined, or no longer referenced) fails too.
- **Maintainer tooling: design-token gate now also checks theme coverage completeness**. The same script asserts that any token defined by one theme (`frontend/themes/*.css`, excluding the `*.example.css` template, which is not linked by `index.html`) is explicitly defined by **every** other theme — a token present in one preset and missing in another silently falls back to the dark `:root` value, which is exactly how the IDE highlight colors used to break under the light preset. The required set is derived mechanically from the union of what the themes define (no hand-maintained must-define list), and tokens a theme is *meant* to change (font family, radius scale) are exempted via `THEME_IDENTITY_TOKENS` in `scripts/css_tokens_check.py`. Enabling it backfilled `--shadow-card` and `--terminal-panel-bg` / `-border` / `-fg` into `material.css` and `high-contrast.css` with values tracking the existing `tokens.css` / `light.css` ramp, so there is no intended visual change.
- **Maintainer tooling: CSS literal budget gate**. New `scripts/check-css-literals.sh` (pre-commit hook + part of `check.sh`) counts, per file in `frontend/styles/*.css` (excluding `tokens.css`, whose job is to hold literals), `font-size` literals and color literals (`#hex` / `rgb()` / `hsl()` / `white` / `black`) and compares each count with the per-file budget in `scripts/css_literals_budget.txt`. The comparison is **exact equality**, following the repo's "a stale entry fails" allowlist style rather than a plain ceiling: adding a literal fails, and cleaning one up without lowering the budget fails too, so the table is a ratchet that cannot rot into a blanket exemption. The starting point was 166 `font-size` + 26 color literals across 13 stylesheets (theme files are out of scope — defining colors there is their purpose); the `font-size` side is since ratcheted to 0 (see the type-scale entry below), leaving the color side. A stale entry (file gone, out of scan scope, or both counts 0) fails as well.
- **Design system: single font-size scale, `font-size` literals driven to zero in `frontend/styles`**. `tokens.css` now carries a 13-step px type scale (`--text-2xs` 9px … `--text-7xl` 22px, ordered by ordinal rather than by role so a step can be re-pointed without renaming). The unit is always `px` — the root font-size is now `--text-lg` itself (`html, body { font-size: var(--text-lg) }` in `base.css`), so `rem` stays a conversion factor for one anchor and never becomes a second convention. All 166 `font-size` literals (110 `px` / 40 `rem` / 16 `em`) collapsed onto that scale by nearest rendered size (±0.5px, ties going to the larger step — the seven `0.75rem` = 10.5px declarations therefore land on `--text-sm` = 11px); the largest shift is the two decorative glyph sizes in `.chat-tui-think-summary` (rendered 8.5 / 8.0px under a 10px parent) snapping up to `--text-2xs`. Every `em` is gone: the 11 whose parent font-size is a fixed token now reference that token's neighbour step, and the 5 inside the chat column (inline `code`, the skill chip, file refs) became `calc(var(--crabmate-chat-font-size, 14px) * <ratio>)` so they still scale with the user's chat-font preference instead of being frozen. Two drifted fallbacks were aligned while touching the same declarations (`--crabmate-chat-font-size` fallback `0.875rem` → `14px`, matching its other consumer; the stale `var(--text-xs, 12px)` fallbacks on `.chat-tui-think-summary` / `-body` dropped — the token always exists, and 12px contradicted its own 10px value). `scripts/css_literals_budget.txt` ratchets every `font-size` budget to 0 (the five entries that were then down to a zero count in both fields are removed, as the gate requires); the 26 remaining color literals are untouched and tracked for the follow-up color pass (the semantic pass below takes them to 20).
- **New `shadcn` dark preset** (visual addition, no behavior change). A fifth theme joins `light` / `material` / `high-contrast` for users who prefer the shadcn/ui look: a zinc near-black elevation ramp (`#09090b` → `#0f0f11` → `#18181b`, `--surface-hover` / `--border` at `#27272a`), 1px hairline borders, a restrained blue accent (`#60a5fa`) with decoupled info/success/warn/error colors, squarer radii and the **Inter** font (`--font-sans`, so it is an identity-token change and not a coverage gap). It is a pure design-token CSS overlay like the other presets — **no Tailwind, no component library and no new dependency**: shadcn/ui is only the design language here, and the existing Leptos markup renders unchanged. `themes/shadcn.css` defines the full theme-coverage token set (`--terminal-panel-*` kept at the family value, all `--ide-hl-*` included) so the token gate stays green, and its semantic colors plus `--muted` stay ≥4.5:1 on its `--bg` / `--surface` / `--surface-hover` layers (the primary button's white label is ≈5.5:1). `--inset-highlight` and the shadow/scrim tokens are referenced but not redefined, so nothing is added to the must-define set and the other presets are untouched. The Google Fonts link in `index.html` gains `Inter` (both the async and the `noscript` copy), and the slug is registered in `THEME_SLUGS` / `THEME_CSS_SLUGS` with a settings-page label, so it shows up in the theme dropdown automatically. Its look was then tightened toward real shadcn/ui: the inset white highlights are gone from `--shadow-raised` and `--composer-bar-box-shadow` (that inner glow is a Linear/Vercel trait, not shadcn's), the page halos are off (`--page-bg-decor-html` / `-body` → `none`, i.e. a flat base color), and the radius ladder is corrected so `--radius-lg` is `8px` — shadcn's `--radius` = `0.5rem` — with `--radius-xl` following to `12px`.
- **New `shadcn-light` preset** (visual addition, no behavior change). shadcn/ui's actual default look is light, so the `shadcn` preset now has a light counterpart: zinc-50 base (`#fafafa`) with white cards, zinc-200 hairlines (`#e4e4e7`), the same restrained blue accent at blue-600 (`#2563eb`), blue-600-tinted selection, and **Inter** — the same identity tokens (font, radius ladder) as the dark preset, so switching between the two keeps the shape and only flips the palette. ### Changed

- **Theme presets now follow a light/dark naming convention, and the default theme is `shadcn-light`.** Every preset whose scheme is fixed carries an explicit suffix — the base themes `dark` / `light` become `crabmate-dark` / `crabmate-light`, and `material` / `high-contrast` / `shadcn` become `material-dark` / `high-contrast-dark` / `shadcn-dark`; `shadcn-light` keeps its name, and `system` (no single scheme) stays suffix-free and resolves to `crabmate-dark` / `crabmate-light`. The theme stylesheets were renamed to match (`themes/light.css` → `themes/crabmate-light.css`, `themes/material.css` → `themes/material-dark.css`, …), so the `data-theme` attribute and the `<link>` list in `index.html` carry the new slugs; the settings-page dropdown labels gained the matching "深色 / 浅色" (Dark / Light) wording. The default theme is now **`shadcn-light`**: it is applied when no preference is stored (the shell used to stay on the dark first-frame baseline, so a new user never saw the default) and when an unknown value is read. **Old slugs are not aliased** — a stored `light` / `dark` / `material` / `high-contrast` / `shadcn` resolves to the new default `shadcn-light`; the first-frame baseline deliberately stays the dark `crabmate-dark`, which is not the default, so dark-theme users still see no light flash before `GET /user-data/prefs` returns.
- **Modal skeleton convergence: every dialog root now goes through one `FocusableModalPanel`.** The shared shell in `frontend/src/app/focusable_menu.rs` (already used by three dialogs) absorbed the nine remaining hand-written modal roots — IDE new-file, workspace clone, approval, settings, workspace project, session list, mobile changelist, the model-registry add-model dialog and the workspace file picker — so `role` / `aria-modal` / focus trap / Escape / focus restore are declared once. The shell grew the props those call sites needed: `dialog_role` (defaults to `alertdialog`; plain dialogs pass `dialog`), `labelledby` (`aria-labelledby` on the panel), `testid` (renders `data-testid`, previously a gap for the session list), `stop_pointerdown` (for panels that sit above a window-level menu / swipe listener) and `on_escape`. Behaviour notes: the settings dialog is the one **semantic change** — it now closes on Escape as well, routed through the existing dirty-form guard (`request_settings_modal_close`), so an unsaved draft still asks before being discarded; the clone dialog deliberately keeps ignoring Escape while the clone is running; and every panel's keydown now also `prevent_default` / `stop_propagation` except during an IME composition, which the hand-written versions mostly did not. Call sites keep their own state-reset / autofocus effects but no longer carry their local `focus_first_in_modal_container` fallback (the shell owns first focus), and their `role="dialog" aria-modal="true"` literals are gone — enforced by the modal shell gate below. Two `E0525` errors surfaced during the move: `Show`'s children must be `Fn` (not `FnOnce`), and a panel written inline inside the `Show` children closure captured non-`Copy` values (the `Arc` callbacks, a form-signal struct) **by value**, moving them out of the outer closure and degrading it to `FnOnce`; each panel is therefore extracted into its own `#[component]`, whose body is not under that constraint and which the `Show` closure only `.clone()`s into. The chat image lightbox is the one root still outside the shell (its overlay is built with `create_element` / `set_attribute`, not a Leptos view). Not in scope and left as-is: the 13 duplicated `.modal-backdrop` wrappers, whose close-on-self-click test had already diverged (bare `on:click` vs. `mouse_event_target_is_current_target`).
