# Client surface capability matrix

> **Audience**: contributors aligning Desktop / Android / Web / TUI.  
> **Not**: HTTP/SSE contracts (Server) or crate-extract planning ([`client_shared_logic.md`](./client_shared_logic.md)).  
> **Maintenance**: a PR that changes a surface’s user-visible capability **must** update the matching cell here in the same change.

## Surfaces (columns)

| Column | What it is |
|--------|------------|
| **Desktop** | Linux Tauri shell + packaged `frontend/` WASM |
| **Android** | Tauri shell + **same** WASM; extra Kotlin / FGS |
| **Web** | Same WASM hosted by `crabmate-web` (or equivalent) in a normal browser |
| **TUI** | `crabmate-tui` (HTTP/SSE serve client in `src/serve`; not the WASM UI) |

Desktop, Android, and Web share one UI crate. Do not treat them as three independent products. TUI is a separate client. Execution stays on a running `crabmate serve`.

## Cell vocabulary

| Token | Meaning |
|-------|---------|
| **yes** | Shipped on this surface |
| **reduced** | Shipped with a documented downgrade (see Notes) |
| **no** | Intentional non-goal — do not “align” other surfaces to match |
| **planned** | Written in a design doc; not shipped |

Blank cells are forbidden.

When the serve workspace is not set (empty root path) the right sidebar shows an explicit "not set" hint. `p` in the workspace tree opens the **project pool picker** in both cases (`GET /workspace/projects`; `POST /workspace/projects` switches and refreshes the tree — TUI only, no new serve contract): with no root it picks a first project, with one already set it switches to another serve project. `/workspace [path]` (alias `/cd`) does the same switch **by path** from the composer — `GET /workspace` shows the current root, `POST /workspace` sets it, and `/workspace off` (also `none` / `clear` / `default`) restores the serve default by sending an empty path — the command form is needed because a bare `/workspace` means "query". The client applies **no allowlist**: it posts the path verbatim, with one exception — `~` / `~/…` is expanded client-side against the **client's** `HOME` (only equivalent when TUI and serve share a machine; `CM_TUI_EXPAND_TILDE=off` hands `~` to serve instead), and `~user` is refused without sending a request — and otherwise only reports the Server's `ok` / `error`, so whether a directory outside the project pool is accepted is a **serve-side policy** decision, not a client one (the pool gates only the `…/projects` picker); both paths end in the same reset (tree + expanded set cleared, root re-fetched) and neither touches the conversation. Sidebar columns are **runtime-resizable and remembered** — drag either divider (the panes now draw a border line each; a press on it starts the drag, a `Drag` recomputes the width from the pointer column rather than accumulating deltas, and a lane click is only ever a press, so dragging through the connection list does not switch lanes), the result is clamped per column and against the terminal budget (the right column yields first, the chat column is floored at 40 cells), and releasing persists it to the local `$XDG_STATE_HOME/crabmate/tui-panes.json` (**only the column that was dragged**: the other may be squeezed by the budget rule, and that squeeze is a display-layer conclusion, not a preference) so the next start restores it; the widths are hidden on narrow terminals rather than at a fixed 120-column rule; switching sessions **replays** that session's history from `GET /conversation/messages` (newest page, then `/older` prepends earlier pages through `before_index` — 80 per page — shifting the tool-call map and the search anchor with the rows, re-scanning an active `/find` search over the prepended page, and staying pinned when the viewport was already at the top — a further PgUp at the top keeps paging silently), and **startup no longer adopts the Server's `active_session_id`** — the first sessions refresh only marks it active in the sidebar; a replay happens solely for an explicit `--conversation-id`, which also **rebinds** that conversation (`/conv new` starts a fresh one), a failed fetch keeps the current screen and rolls the binding back, and `/older` (alias `/history`) prepends the next page of earlier messages (`before_index` from the reply's `window_start_index`; the completion line names `/older` instead of implying the conversation starts there, and a reply that lands after a session switch is dropped). `/background [path]` paints a full-screen background **under** the transcript: kitty graphics (real pixels, `z=-1` so text stays on top) on kitty / Ghostty / Konsole / Warp, and per-cell background colours (the image downsampled to `columns × rows`, a mosaic that needs no terminal protocol) everywhere else — 256 colours are the only prerequisite, off by default, `off` clears it, and cells whose background is not one of the two theme fills (bubbles, borders, search hits, selections) are left alone. `crabmate-tui caps` prints that probe (`TERM` / `TERM_PROGRAM` / `CM_TUI_IMAGE` → picked tier); it reads environment variables only (no active query) and deliberately under-reports inside tmux / screen, where `CM_TUI_IMAGE=kitty` is the explicit override. Transcript Markdown images still degrade to `[图] alt` — only the background draws real pixels. The status bar also carries a **context-window usage** segment (`ctx 116.9k / 1000k (11.7%)`), measured server-side from `tiktokenPromptTokens`（`RUN_FINISHED` / `conversation_saved`） (not a local estimate), with the denominator taken from the local `context_tokens` setting first and `max_input_tokens` only as a fallback; a per-`conversation_id` watermark keeps it monotonic so the wobble from L5-skill reselection does not flicker, and the segment is always rendered — before any measurement it shows the placeholder `—` rather than disappearing. The palette otherwise follows the Desktop theme name from the serve prefs, overridable with `CM_TUI_THEME`; the **default** preset is `shadcn-transparent`, which sets `bg` + `chrome_bg` to `Color::Reset` so the UI draws on the terminal's own background (cells have no alpha, so there is no half-transparent variant; unknown preset names are ignored, and `default-dark` restores the solid dark look). **Multiple serves in one process**: `--connect <name>=<url>` (repeatable; the main `--api-base` connection is always the first lane, named after the ctl instance whose `base_url` matches it (falling back to `local` when the control plane is absent or that URL is undeclared, so `/lane attach <instance>` hits it), and its bearer is reused) adds more lanes, and the left column's lower half lists every connection as a stack of full-width tinted bars (`连接 [n/8] ▲k` header, then exactly one row per connection — active lane on the selection colour with a `▎` bar — stacked downward), taking a **fixed half of the left column** regardless of how many lanes exist, **even when there is only one** — with a single lane the pane used to be hidden, which left “which serve am I on” and “does this client support more than one” invisible. Switching is `Alt+←/→`, `Ctrl+N` (the same hotkey as `Alt+→`, not a second "next" rule), `Alt+1..8` (**straight to lane n**, absolute and never wrapping — an out-of-range number leaves the view alone and writes one line, since `Alt+digit` is exactly the chord a terminal or tmux likes to swallow, and a silent no-op reads as "my key was never delivered"), or a click anywhere inside a block, and it only switches the view: running turns, drafts and scroll positions stay in their own lane. Each row's single status symbol is `·` idle, `●` running, `▲` waiting for an approval decision, or `×` **already asked to quit** (ranked above the other two, since the wait between `/quit` and the process actually exiting can span a whole turn) — so a request made on one lane cannot go silent while you work in another. Each row also carries that serve's **current workspace tail** (`name · project`, from `GET /workspace`; the full path stays in the right column's title, and a row too narrow for 4 spare columns drops the tail rather than squeezing it) — `POST /workspace` is **one workspace per instance** (a different path on a bound instance answers `409 WORKSPACE_ALREADY_SET`), so without it you cannot tell whether two lanes point at the same project, which is the usual way to switch to the wrong one. That 409 is classified separately in `crabmate-client-api` (`classify_workspace_set_failure` → `WorkspaceSetErrorKind::AlreadySet`, keyed on the **top-level** `code`, never on the message text) and reported as "already bound elsewhere; start another lane", not as a retryable "switch failed". Runtime lane **creation is wired through the control plane**, and so is local lane *closing* (`/lane detach`, which drops this process's connection only — declarations and serve processes are untouched): `--ctl-socket <path>` (or the default `$XDG_RUNTIME_DIR/crabmate/ctl.sock`, auto-enabled only when it already exists) gives `/ctl` — a read-only instance list, counting an instance as connectable **only when `observed == ready`** (never `state` — `stale` would dial a dead port) — and `/lane`, whose `list` subcommand is that same query while `attach <name>` connects an already-ready instance and `new <name> [workspace] [profile=<name>]` writes a declaration through the socket's `add` (the `profile` is a **name** for a `profiles.toml` preset: forwarded as-is, never inline config and never pre-read by the client, so a typo comes back as the Server's own error), polls `list` every 300 ms until the instance is ready (20 s cap; a timeout says "still starting, check `/ctl`" instead of "failed"), then connects — no process restart. While that poll runs the row already exists as `◌ <name>` (a declaration written, not yet a connection): it becomes a real lane on success, `✗ <name>` with the Server's own reason on failure, and stays `◌` with a `超时` note on a timeout — and because it is not in `lanes`, it sits *below* the connections and is **not** clickable, so a click can never switch to the wrong lane. The declaration is written by `crabmatectl` alone: the client never touches `instances.toml`, which `--watch` also writes, and it never spawns `crabmatectl` itself. The workspace for `new` is the explicit argument or the current lane's serve workspace (`add.workspace` is mandatory over the socket; port binding only works for TOML declarations), and `created: false` for an already-declared instance is an idempotent hit rather than a failure. An attached lane reuses the **launch-time** prefs (a `/model` override stays with its own lane), runs the same first refresh as startup, and attaching a name that is already connected — or a **different name on a `base_url` some lane already holds** (`same_api_base`: trailing slash and case are cosmetic, `localhost` and `127.0.0.1` stay two Origins) — only switches to it, so one `serve` never ends up as two lanes. `/lane detach [<name>]` drops only the local connection (no argument targets the lane you are in, so its name need not be looked up first): the `LaneApp` is dropped, which closes the worker's job channel (its thread and runtime wind down), the removed lane's late events are discarded by `LaneId`, the last lane cannot be detached, and an unknown name lists the ones that do exist. `/quit` is the **process-level** verb (it ends the client from any lane — a request pending behind a running turn takes effect as soon as that turn settles, instead of waiting for you to switch back; dropping one connection is `/lane detach`), and on the way out **every** lane's composer draft is written back to the session index — one shared time budget split across the lanes left, so a dead `serve` cannot starve the rest — not just the focused lane's. Declaration-level closing is wired too: `/lane close <name>` (alias `disable`) flips the declaration to `enabled = false` through the socket and `/lane open <name>` (alias `enable`) undoes it, so closing a lane no longer means reaching for `crabmatectl`, and readiness reads `enabled` **before** `observed` (#373) — otherwise a just-closed instance answers "not ready yet", because the Server reports `starting` for a declaration that has no state record — the declaration, its hand-written `env` / `config` and the client's own connection story stay separate (`/lane detach` is still the local half, and `remove` is still not wired because it would hard-delete those hand-written keys). Three Server semantics are reported rather than re-derived: `changed: false` is an idempotent hit ("it already was like that", not a failure), `enable` also clears the `down` marker (`cleared_down`), and a half-done `enable` still answers `ok` with a `warning` that is surfaced — otherwise it reads as "the declaration is enabled, the instance never starts". When the client is connected to the named lane it detaches it after the declaration is off (the instance is about to be stopped, so the connection is a dead SSE); the **only** exception is the last remaining lane, where the consequence is spelled out instead so the UI keeps something to draw. A cap of **8 lanes** is enforced on both paths (`MAX_LANES`): launching past it fails fast instead of silently connecting the first eight, while `/lane attach` / `/lane new` on a running client only answers in the lane that asked (and both still switch to an already-connected lane at the cap, since that adds nothing). **`F4` jumps to the next lane waiting for an approval** (ring search from the lane after the current one; nobody waiting leaves the view alone and says so), so a background overlay no longer has to be hunted for with `Alt+←/→`. **Not done yet**: no waiting-to-bind marker on a row whose workspace came back empty. The **left column's lane header** carries the cap and the global approval count: `连接 [n/8] ▲k` (`▲k` only while some lane waits — never `▲0`, and the header truncates as one string, so no segment count can drift). These two numbers used to live in a separate `lanes` segment of the status stack — the same readings in the opposite corner of the screen — which is why they now sit where `/lane attach` and `F4` act (an approval request in a non-active lane still waits in that lane's own overlay). |
| `POST /chat/stream` + command approval | yes | yes | yes | yes | Android: notification keep-alive. TUI: repl TTY prompt; full-screen approval overlay (Enter/once · a/always · Esc/n/deny) or `--yes`; `Ctrl+E` expands the overlay to the whole command (wrapped by display width, scrollable with arrows/PgUp/PgDn/Home/End), collapsed it is one truncated line. |
| Clarification questionnaire (`clarification_questionnaire` → next request's `clarify_questionnaire_answers`) | yes | yes | yes | yes | The Server may answer a turn with a 1–12 question form; the answers ride the **next** request, so this is not a blocking gate like approval. Web / Desktop / Android: the composer's form (required fields validated, one stub user bubble). TUI (#424): the question set was previously **dropped on the floor** — `SseClarifyTraceHooks::default()` registers no hook, so the event fell through to `Skip` and the user only saw the tool row. Now it becomes a modal form (`Tab`/`↑↓` question, `Enter` submit, `Esc` collapse). It opens **when the turn ends**, not when the event arrives: the Server emits it right after a tool succeeds, while the turn is still streaming, and an overlay at that moment would cover the transcript being written. Submitting goes through the same `start_turn` path with one extra field (`start_turn_with_clarify`), so there is no second send route. Three deliberate behaviours: (a) required-field failure jumps the cursor to **that** question and names it (a 12-question form cannot just say "something is missing"); (b) `Esc` collapses but **does not** discard the drafts — it says so plainly, because silence reads as "already submitted"; (c) `kind: choice` only renders a 「选择题」 badge and is still answered as text — the 0.8.0 contract has no options list, so inventing candidate keys would be a fabricated affordance.
