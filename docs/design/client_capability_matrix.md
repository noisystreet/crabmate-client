# Client surface capability matrix

> **Audience**: contributors aligning Desktop / Android / Web / TUI.  
> **Not**: HTTP/SSE contracts (Server) or crate-extract planning ([`client_shared_logic.md`](./client_shared_logic.md)).  
> **Maintenance**: a PR that changes a surface’s user-visible capability **must** update the matching cell here in the same change.

## Surfaces (columns)

| Column | What it is |
|--------|------------|
| **Desktop** | Linux Tauri shell + packaged `frontend/` WASM |
| **Android** | Tauri shell + **same** WASM; extra Kotlin / FGS |
| **Web** | Same WASM hosted by `crabmate-web` (or equivalent) in a normal browser |
| **TUI** | `crabmate-tui` (HTTP/SSE serve client in `src/serve`; not the WASM UI) |

Desktop, Android, and Web share one UI crate. Do not treat them as three independent products. TUI is a separate client. Execution stays on a running `crabmate serve`.

## Cell vocabulary

| Token | Meaning |
|-------|---------|
| **yes** | Shipped on this surface |
| **reduced** | Shipped with a documented downgrade (see Notes) |
| **no** | Intentional non-goal — do not “align” other surfaces to match |
| **planned** | Written in a design doc; not shipped |

Blank cells are forbidden.

### Chat and tools

| Capability | Desktop | Android | Web | TUI | Notes |
|------------|---------|---------|-----|-----|-------|
| Full-screen TUI (ratatui) | no | no | no | yes | `crabmate-tui tui`: status bar + session sidebar + streaming transcript + composer. A submit while a turn is running is **queued** and sent once that turn completes cleanly (Esc clears the queue; a cancelled or failed turn puts the text back into the composer instead of sending it), and each conversation keeps its own composer draft across session switches — `/conv new` starts empty — but that table lives in memory only, so a draft left on a switched-away conversation does not survive the process; the active one is written back to the session index on exit. M1: stream + Ctrl+C cancel; M2: session sidebar with use/new + `/status` serve-default linkage (`/conv new` also writes the shared session index — reuse-or-insert a blank row, bind the first turn's id back into it, reclaim the row when leaving it unsent, and name it from the first message — so a TUI-created session appears in Web / Desktop too); M3: approval overlay (Esc=deny), thinking fold (Ctrl+E), one-line tool summaries, `/find` search, paged scroll, multi-line input (Alt+Enter, and a **pasted block lands whole** — bracketed paste is enabled, so newlines inside a paste never turn into submits and a pasted `Tab` never moves focus; `CM_TUI_PASTE=off` opts out), the current workspace name shown in the session/workspace column titles (via `GET /workspace`), and inline Markdown styling for assistant text (bold/italic/code/link/strike; code fences stay plain); M4: **workspace directory tree browse** in the **right-hand column, shown by default on wide terminals** (Desktop-style; Ctrl+W focuses it for ↑/↓ navigation, expand/collapse directories on demand via `GET /workspace[?path=]`, Enter on a file inserts its workspace-relative path into the composer, → only expands, Home/End/PgUp/PgDn jump or page, `r` refreshes while keeping expanded folders and restores the cursor once their listings reload, `w` returns to the sessions list), and the tree is **mouse-operable** (a click focuses the column and lands the cursor, then toggles a directory row / selects a file row, the wheel moves the cursor over the tree once it has focus (elsewhere it scrolls the chat), a click outside the tree returns focus to the composer; `CM_TUI_MOUSE=off` restores the terminal's native drag-select copy). The **session column is mouse-operable too**: one click selects that session and switches to it (the same `use_selected` path as `Enter`, so a running turn still refuses the switch and a row without a `server_conversation_id` still answers with its hint), a click on the column title or the bottom hint row only takes focus, a click anywhere in the column cancels a pending delete confirmation (same rule as moving the focus), and the **wheel deliberately leaves the list alone** — its window follows the selected row, so scrolling could only mean "move the selection", which with click-to-switch would change sessions on a stray tick — it keeps scrolling the transcript instead. `/copy [assistant|user]` (alias `/yank`, or **Ctrl+Y** from any focus) puts the **latest non-empty message of that kind** on the clipboard as original Markdown: SSH sessions go through **OSC52** (the only route that reaches the local clipboard when the client runs on a remote host), local sessions prefer `wl-copy` → `xclip` → `xsel` and fall back to OSC52, tmux gets the passthrough wrapper (server-side `allow-passthrough on` required) while **screen refuses OSC52 outright — external tools only there** — payloads above ~64 KiB base64 are flagged as possibly truncated rather than reported as a clean copy, a tool that cannot run (no `DISPLAY` / no wl service) falls back to OSC52 once, and `CM_TUI_CLIPBOARD=off\|osc52\|tool` forces a route. When the serve workspace is not set (empty root path) the right sidebar shows an explicit "not set" hint. `p` in the workspace tree opens the **project pool picker** in both cases (`GET /workspace/projects`; `POST /workspace/projects` switches and refreshes the tree — TUI only, no new serve contract): with no root it picks a first project, with one already set it switches to another serve project. `/workspace [path]` (alias `/cd`) does the same switch **by path** from the composer — `GET /workspace` shows the current root, `POST /workspace` sets it, and `/workspace off` (also `none` / `clear` / `default`) restores the serve default by sending an empty path — the command form is needed because a bare `/workspace` means "query". The client applies **no allowlist**: it posts the path verbatim, with one exception — `~` / `~/…` is expanded client-side against the **client's** `HOME` (only equivalent when TUI and serve share a machine; `CM_TUI_EXPAND_TILDE=off` hands `~` to serve instead), and `~user` is refused without sending a request — and otherwise only reports the Server's `ok` / `error`, so whether a directory outside the project pool is accepted is a **serve-side policy** decision, not a client one (the pool gates only the `…/projects` picker); both paths end in the same reset (tree + expanded set cleared, root re-fetched) and neither touches the conversation. Sidebar columns hidden below 120 columns; switching sessions **replays** that session's history from `GET /conversation/messages` (newest page, then `/older` prepends earlier pages through `before_index` — 80 per page — shifting the tool-call map and the search anchor with the rows, re-scanning an active `/find` search over the prepended page, and staying pinned when the viewport was already at the top — a further PgUp at the top keeps paging silently), and the Server's active session is replayed the same way on the first sessions refresh after startup — startup replay also **rebinds** that session, so the next message continues it (`/conv new` starts a fresh one), a failed fetch keeps the current screen and rolls the binding back, and `/older` (alias `/history`) prepends the next page of earlier messages (`before_index` from the reply's `window_start_index`; the completion line names `/older` instead of implying the conversation starts there, and a reply that lands after a session switch is dropped). `/background [path]` paints a full-screen background **under** the transcript: kitty graphics (real pixels, `z=-1` so text stays on top) on kitty / Ghostty / Konsole / Warp, and per-cell background colours (the image downsampled to `columns × rows`, a mosaic that needs no terminal protocol) everywhere else — 256 colours are the only prerequisite, off by default, `off` clears it, and cells whose background is not one of the two theme fills (bubbles, borders, search hits, selections) are left alone. `crabmate-tui caps` prints that probe (`TERM` / `TERM_PROGRAM` / `CM_TUI_IMAGE` → picked tier); it reads environment variables only (no active query) and deliberately under-reports inside tmux / screen, where `CM_TUI_IMAGE=kitty` is the explicit override. Transcript Markdown images still degrade to `[图] alt` — only the background draws real pixels. The status bar also carries a **context-window usage** segment (`ctx 116.9k / 1000k (11.7%)`), measured server-side from `tiktokenPromptTokens`（`RUN_FINISHED` / `conversation_saved`） (not a local estimate), with the denominator taken from the local `context_tokens` setting first and `max_input_tokens` only as a fallback; a per-`conversation_id` watermark keeps it monotonic so the wobble from L5-skill reselection does not flicker, and the segment is always rendered — before any measurement it shows the placeholder `—` rather than disappearing. The palette otherwise follows the Desktop theme name from the serve prefs, overridable with `CM_TUI_THEME`; the **default** preset is `shadcn-transparent`, which sets `bg` + `chrome_bg` to `Color::Reset` so the UI draws on the terminal's own background (cells have no alpha, so there is no half-transparent variant; unknown preset names are ignored, and `default-dark` restores the solid dark look). |

| In-app stream resume after background | yes | yes | reduced | yes | TUI: repl records a dropped run's `x-stream-job-id` + `last_event_id` and `/resume` re-attaches with `stream_resume:{job_id,after_seq}`; the full-screen `tui` keeps the same kind of resume point (a transport interruption, or Ctrl+C whose cancel request was not acknowledged) and `/resume` in the composer re-sends the same message with `stream_resume`, without echoing the user line again — switching sessions or `/conv new` drops the point because the transcript is no longer the one that broke. | Per-turn inject / trim transcript notes | yes | yes | yes | no | WASM: Server `timeline_log` `context_inject` / `context_trim`; **hidden by default**; Settings → Appearance. | Permission-level projection (`GET /permission`) | reduced | reduced | reduced | reduced | Desktop / Android / Web: permission block in **Settings → Tools** — current level (+ `level_source`), server ceiling (+ `ceiling_source`), the selectable set (`available`), and why it was narrowed (`clamped_by`, in the fixed `ceiling → role → session_mode` order; unknown axes dropped). Served by `crabmate-client-api::permission` (vocabulary + `paths::permission`, see [`client_shared_logic.md`](./client_shared_logic.md) §4.16). **Reduced**: the ceiling itself has no write route (`available` is listed, the ceiling is not writable) — the selector only picks among the served `available`. A serve without the route answers 404 and is reported as *not supported* instead of as an error (that 404 **is** the capability probe; `/status` succeeds on old and new serve alike and cannot tell them apart). `agent_role` / `conversation_id` are not sent yet, so the figure is the static projection, not the per-turn one. **Now also writable, one idle-time route**: the block carries a level selector (options = the served `available` only), and picking one sets the intent signal shared with the chat sender (`ChatShellLeptosContext`), then — when a conversation is already bound — `POST /conversation/state` persists it and the response's own projection refreshes the block. With no bound conversation the pick is local only and says so ("applies to your next message"): the Server deliberately does not upsert an empty conversation row. Still `reduced`, not `yes`, because the ceiling itself has no write route and the per-turn figure is not shown. The **status bar** carries the same control as a chip (`perm 意图 → 生效`, menu reusing the mode menu's portal): it shows `intent → effective` only when they differ, renders nothing when neither is known (never falling back to `/status`'s `permission_level_default`), and is cleared when you switch conversations — the intent remembers which local conversation it was picked for. TUI: the status bar's environment segments end with `perm <level>` (wire value, e.g. `perm approved`) — the **lowest-priority** segment, so a narrow terminal drops it before `ctx` / `find`. It rides the same worker job as the serve defaults (`/status`), and a 404 / fetch failure leaves the segment out entirely rather than falling back to a configured default: the shown value is always "what serve says is in effect now", never a guess. **Writable from the terminal too**: `/perm [<level>]` (repl and full-screen `tui`, `off` clears) is a client-side override on the same footing as `/mode` / `/role` — it rides the next turn's `permission_level` and is **not** validated client-side, since the selectable set belongs to the server's `available` and a hard-coded vocabulary would reject a newly added level. Details (ceiling / `available` / `clamped_by`) stay on Desktop **Settings → Tools**. |
