# 目录聚合行数预算（门禁：scripts/check-layout-budget.sh → scripts/layout_budget_check.py）
#
# 为什么：920 行单文件硬帽（fn-nloc）只防巨型文件，却成了事实上的模块划分依据 ——
# 全仓 651 个 .rs 里 26 个落在 850–920 行、16 个 ≥900 行，`worker.rs` 与 `tui_mode/mod.rs`
# 正好 920 行整。拆成 8 个 900 行文件曾是免费通行证；本文件给「一个域」也设上限（#597）。
#
# 格式：<dir>  lines=<n>  scope=<recursive|direct>   # <理由 / 目标>
#   - 实际 .rs 物理行数必须**等于** lines：写多写少都 fail
#     （少写 = 给后续增长留免费额度，这正是要堵的口子；变瘦了就同步下调，ratchet）；
#   - scope=recursive 递归统计、scope=direct 只统计直接子文件；
#   - recursive 条目不得是另一条目的祖先（嵌套登记 = 重复计数，门禁会拒）；
#   - 理由必填且不许留 TODO；条目陈旧（目录没了 / 已无 .rs）同样 fail。
#
# 基线由 `python3 scripts/layout_budget_check.py --print-baseline` 生成（数字永远实测），
# 候选目录（≥ 3,000 行）用 `--print-candidates` 列。选哪些登记是评审判断：
# 例如 crates/crabmate-tui/src（66,459）与其中的 tui_mode（57,503）嵌套，只登记后者更有意义。
#
# 归属守恒（Rule C）目前只对 frontend/src/app 生效：app 递归总行数必须等于
# 「根级 direct 预算 + 各直接子目录 recursive 预算」之和 —— 任何新目录都会以「未归属行数」暴露。
# 其它根按需登记（不套守恒），理由见脚本头注释。
